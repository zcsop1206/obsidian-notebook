# S42: Today shows today's day file first

Brief by claude, 2026-11-20. Read docs/study/BOARD.md (how to work here) and SPEC.md (Today and Map) first.

**0.15.1 if merged by 2026-11-24, else 0.16 · claude · panels only.** Merged before S26a starts on `panels/*`.

**Goal.** Each morning the laptop planner (outside this repo) writes a day file, `<study root>/plan/<YYYY-MM-DD>.md`: one ordered list of what Adit should do that day, each row with its minutes and the deliverable it serves. Today shows that list first, so the iPad has one place that says what to do now. Without a day file, Today is exactly what 0.15.0 shows.

**The day file** (written once by the laptop, then edited only by Adit; the plugin never creates one):

```
---
study: plan
---
# Sat 11-21 · 360 min
Generated by pm/plan.mjs for Adit. Not Adit's words; ... Work from the top; on a short day, stop where the time runs out.

- [ ] 30 · drills · Today's drills (fx-div is 2 days overdue)
- [ ] 30 · putnam · settle the 2 open calls (Today lists them)
- [x] 75 · putnam · first pass [[fx-units]], part 1 of 2
- [ ] 45 · putnam · **Putnam timed half paper, then settle and score it**
- [ ] 45 · private
- [x] 60 · mie301 · extra
hours 2026-12-12 60
answer asic-1 a
```

- A **row** is a checkbox line `- [ ] <minutes> · <rest>` or `- [x] …` (`*` bullets and `X` too). `<rest>` is `<deliverable> · <label>`, or just `private`. Rows Adit adds at the bottom are rows like any other.
- The label may hold `[[doc-id]]` or `[[doc-id|alias]]` links and `**bold**` (a fixed event). Nothing else in it is markdown that needs rendering.
- Every other line (frontmatter, the `#` header, the label line, `hours …`, `answer …`, blank lines) is not a row and is not shown. `study: plan` parses as kind `other`, so the index skips the file.

**Scope.**
1. **`src/study/panels/plan-day.ts` (new):** a pure parser, `parseDayFile(text)` → `{ header: { minutes } | null, rows: [{ line, ticked, minutes, deliverable, label, links }] }`, and the one-line toggle used for ticking, `toggleRow(text, line, expectedRowText)`, which flips `[ ]`/`[x]` on that line only if the line still holds that row (else returns null). No Obsidian imports in the pure part.
2. **`src/study/panels/today.ts`:** when `<root>/plan/<today>.md` exists, where `<root>` is `ctx.settings().root` and `<today>` is the engine's `today()` (the plan's date when there is one), Today shows, right after the date and nearest-deadline lines and before Drills:
   - a section headed "Plan" with the done and planned minutes (sum of ticked rows' minutes / sum of all rows' minutes; the header's day minutes too, if present), and a way to open the day file itself (`ctx.app.workspace.openLinkText`);
   - one row per day-file row, in file order: a checkbox, the minutes, the deliverable, the label (links shown by the doc's title, or the alias, or the id; bold shown bold; the `[[`/`**` markup never shows). A private row shows "private" and its minutes only;
   - tapping a row whose label links a study doc (in `ctx.content().docs`) opens the first such doc with `ctx.ui.openDoc(id)`. Other rows do nothing on tap;
   - tapping the checkbox toggles that row in the file through `ctx.app.vault.process` with `toggleRow`, never opens a doc, and Today then shows the new state. If the line changed under it (sync), nothing is written and a toast says the plan changed and to try again;
   - the "Problems and katas" section moves under a collapsed "More (n)" fold (n = number of picks), whose open or closed state survives re-renders while the panel is open. Drills, Settled today and Requests stay as they are.
   The file is read through `ctx.app` (`getAbstractFileByPath`, `cachedRead`); `context.ts` and `types.ts` do not change. The read is async: a render must never be filled by a read that an earlier render started (a sync arriving mid-read). A day file that changes on disk (an iPad sync, a tick) updates Today: confirm whether `ctx.onChange` already fires for a non-doc file under the root; if not, listen for that one path through `registerEvent(app.vault.on('modify' | 'create' | 'delete' | 'rename', …))`.
3. **Without a day file for today** (none, or only other dates', or the engine stub): Today renders exactly as it does on study-mode today: same sections, same order, same items, no fold. Every existing S8 Today check passes unchanged.
4. **CSS:** the rows reuse the panel's existing `nb-sp-*` look (cards, chips, flags, counts). New rules only for what has no class yet (the checkbox, a ticked row, the fold), in the panels' block of `styles.css`, with the existing colour variables only. Touch targets at least as large as the existing cards; works in light and dark.
5. **Tests:**
   - unit: `test/unit/study-plan-day.test.ts` for the parser and the toggle (rows and non-rows from the sample above, `*`/`X`, a private row, aliases, a label with `·` in it, CRLF, a toggle refused when the line changed);
   - view: a Today section in `test/run_study_test.py` (`part_marks_panels`), with the day file created in the mock vault at run time (do not add files to `test/fixtures/study/`: other tests count its docs). Cover: rows first and in order; minutes total; a link row opens its doc and the private row opens nothing; a checkbox tick changes exactly that line in the vault file and the view shows it ticked; the fold is collapsed with the right count and stays open across a re-render once opened; a vault change to the file re-renders Today; a day file for another date shows nothing; without the file the existing checks pass as before. If the mock vault lacks `process`, add it to `test/mock-obsidian.js` (behaving as Obsidian's: read, transform, write, fire `modify`) and say so.

**Out of scope.** Writing or creating day files (the laptop does that), the `hours`/`answer` lines, `plan.md`, any change to the engine, `context.ts`, `types.ts`, the drills or picks themselves, a release.

**Privacy and hints.** Today shows only what the day file holds. A row never gains a topic, a method or a problem id it does not already name.
