# S12: Problems from Today, as in their doc

Brief by claude, 2026-11-18. Read docs/study/BOARD.md (how to work here), SPEC.md and FORMAT.md first.

**0.15.1 · devin · 5 h · starts now · Adit's iPad checks of 0.15.0 (11-20) may add to it: Claude posts anything they raise about the problem view in the thread.**

**Goal.** A problem opened from Today or Map behaves as it does inside its doc. Its figures resolve, and its call and work ink are the same strokes in both places. This closes the gap the decisions log left open on 11-17: "a problem begun inside its doc and reopened from Today shows an empty call band".

**Scope.**
1. **Home doc.** In `register.ts`, the standalone view's `env.doc` becomes the problem's home doc: `content.problems.get(id).doc`, looked up in `content.docs`. If the problem or its doc is missing, it falls back to the synthetic `problems` doc.
   - Statements render with the home doc's path, so bare-name figures and relative links resolve as they do in the doc.
   - Ink keys stay `call:<id>` and `work:<id>`, and now live in the home doc's ink file.
   - The home doc serves only as the render path and the ink file. Nothing about it (title, id, path) is shown in a hidden pick before the settle, because that would name the topic.
2. **Old strokes:** strokes this device wrote under those keys in `ink/problems.<device>.json` are copied once into the home doc's file for this device. Ids are kept, so a second copy changes nothing. The old file is never edited or deleted.
3. **Image CSS** in `styles.css` (study section): `.nb-study-doc .sr-passage img, .nb-study-problem-view img` get `max-width: 100%; height: auto; -webkit-user-drag: none; -webkit-touch-callout: none; user-select: none`.
4. **The mock resolves images as Obsidian does:** `test/mock-obsidian.js`'s renderer resolves `![alt](href)` through `metadataCache.getFirstLinkpathDest(href, sourcePath)`, emits the resolved vault path as `src`, and marks an unresolved embed `data-unresolved`. Today the mock emits `src=href`, so a test cannot tell a right path from a wrong one.

**Out of scope.**
- Bank problems embedded in another doc: their home stays the bank file.
- Page ink in the standalone view.
- Any change to sessions or events.
- Ink on figures (S13).

**Files owned.** `src/study/blocks/register.ts`; the image rules in `styles.css`; image resolution in `test/mock-obsidian.js`; a section of `test/run_study_blocks_test.py`; additions to `test/unit/study-problem.test.ts`; new fixtures `test/fixtures/study-blocks/s12-*` (an invented problem whose figure sits in a subfolder).

**Interfaces touched.** None. If the ink copy needs a store method that does not exist, that is an `INTERFACE:` entry.

**Acceptance.**
- **Unit:**
  - home-doc resolution for an invented problem, a bank problem and a missing id;
  - the copy of old strokes runs once and is idempotent.
- **View** (blocks test, base + 10):
  - a problem whose bare-name figure sits in a subfolder, opened through `ctx.ui.openProblem`, shows an image with a resolved `src` and `naturalWidth > 0`;
  - an embed naming a missing file is flagged `data-unresolved`;
  - call ink written in the doc's block shows in the standalone view, and the reverse;
  - a hidden pick still shows no doc title or id before the settle (the existing check);
  - `npm run test:study` passes.
- **iPad** (after the release):
  - open a circuits problem with a figure from Today: the figure shows, and a long finger press does not drag it;
  - write a call in the doc, reopen the problem from Today: the call ink is there.
