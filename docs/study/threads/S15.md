# S15: Figure and solution lint, content check, FORMAT

Brief by claude, 2026-11-18. Read docs/study/BOARD.md (how to work here), SPEC.md and FORMAT.md first.

**0.15.1 · claude · 3 h · starts now. Its first commit (the content check's figure serving, already in the working tree) is a wave 1 precondition.**

**Goal.** A missing or wrongly embedded figure, or a detached solution, is caught on the laptop before Adit meets it on the iPad.

**Scope.**
1. **`study-scan --lint`** checks every embed, in every doc and in folded solutions:
   - the embed names an existing file under the root, by bare name, unique in the vault;
   - it has no slash, no `../` and no `![[ ]]`;
   - a solution with no problem, example, derive or recall right above it is an error;
   - a problem whose solution has a figure but whose statement has none is listed as information.
2. **`--figures`** lists figures no doc uses.
3. **`run_study_content_check.py`:** opens every problem that has a figure in the standalone view and checks that its images load.
4. **FORMAT.md:** a Figures section (figures live in `figures/` under the study root, are embedded by bare unique file name `<doc-id>--<slug>.svg` inside the callout that uses them, and have a white background, so they read in dark mode); tracks' `;` sections; `hidden: never`; "an item's solution comes right after it".

**Out of scope.** Checks of what the figures show.

**Files owned.** `scripts/study-scan.mjs`, `scripts/study-scan.test.mjs`, `test/run_study_content_check.py`, `docs/study/FORMAT.md`.

**Acceptance.**
- **Unit:** `study-scan.test.mjs` has a case for each lint rule.
- **Content check** on the portfolio's `content/study` with S12 merged: 0 broken figures, 0 lint errors.
