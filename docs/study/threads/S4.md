**Goal.** Ink on study docs and in blocks that stays attached to the passage it was written on, across rewrites.

**Files.** `src/study/ink/*` (replace the stub `createInkApi`), `test/unit/study-ink.test.ts`.

**Do.**
1. Implement `InkApi` from `src/study/view/host.ts`: `page(doc, stack, passageTop)` draws the doc's page ink over the passage stack in paper px; `surface(doc, container, key, opts)` gives a block its own canvas.
2. Storage per SPEC.md (Ink): `ink/<doc-id>.<device>.json`; read every device's file for the doc, show the union, write only this device's; undo removes only this device's strokes. Save 1 s after the last stroke and on `pagehide` / `visibilitychange`.
3. Anchoring per SPEC.md: on commit, `at = {a, dy, rev, v}` from the nearest anchored passage at or above the stroke's centre. On a new build: follow; dim to 35% with a "changed" chip (keep or delete) when the hash changed; move to an "Orphaned ink" strip when the anchor is gone. `reanchor()` returns the counts.
4. Pen and mouse draw, touch never; prevent stylus touchmove scrolling over the page and surfaces; coalesced events; the look of the notebook's uniform pen (`src/format/outline.ts`), width about 1.6 paper px. Canvas at devicePixelRatio, capped like the notebook's bitmaps.
5. `opts.color` and `opts.meta` for provenance (fog reveals draw in a second colour).

**Acceptance.** Unit tests for the anchoring arithmetic and the reanchor counts (follow, dim, orphan) on two builds of a fixture doc; S3's view test writes strokes with synthetic pen events, reloads the view and finds them in place (add the section; mark it skip until S3 merges if needed).

**Notes.** The demo's `SR.ink` in `lab/study-reader/src/core.js` and the reader's re-anchoring in `reader.js` are the reference; the notebook's `src/ink/input.ts` is the reference for pen feel. Do not change `src/ink/*`; import from it if useful.

ASSUMED: one ink file per doc and device holds page ink and every block canvas of that doc
(`blk` tells them apart), as SPEC.md's example has `blk` in the same file.

ASSUMED: a device never writes another device's file, so deleting or keeping another device's
stroke is recorded in this device's own file as two optional fields: `"hide": ["<dev>:<id>", ...]`
and `"keep": {"<dev>:<id>": "<new rev>"}`; the union applies them. Own strokes are removed or
updated in place. Undo still removes only this device's strokes. FORMAT/SPEC could mention the
two fields (additive, `v` stays 1).

ASSUMED: strokes are keyed `<dev>:<id>` across devices; ids are `s-` + 8 base36 (4 from the clock,
4 random), so two devices cannot collide even if the random part does.

ASSUMED: list items with a block id are anchors of their own; their `rev` is `hash8` of the item's
text, so rewriting one item dims ink only on that item (the list passage's hash covers the rest).
Ties at the same top go to the item over its list.

ASSUMED: `reanchor()` does not change any stroke. It re-reads the doc from `ctx.content()` (falls
back to the doc given to `page()`), re-lays out, and counts page strokes whose `at.v` differs from
the doc's build: moved (anchor and hash unchanged), changed, orphaned. Changed strokes stay changed
until keep or delete; orphans until delete. Keep sets this device's strokes to the new hash and
build. The view decides when to toast the counts.

ASSUMED: changed chips sit in the right margin (`right: 4px`, 108 px wide) 26 px under the
passage's top, so they do not cover a margin dot at the passage's top; they stack without
overlapping. Keep and delete are one tap each (the demo's behaviour; the spec's "nothing is ever
deleted without a tap" holds).

ASSUMED: `surface().clear()` removes this device's strokes in that canvas and hides other
devices' strokes there (a fresh page for the block); `undo()` removes only this device's latest.

ASSUMED: the live stroke is drawn as it comes (quadratics through midpoints, like the demo) and
replaced by the notebook's uniform-pen path (refit centreline, 1.6 px, round caps) at the lift;
a separate live canvas would double the page's canvas memory on the iPad. The difference at the
lift is under about half a pixel (REFIT_RADIUS 1.5 px).

ASSUMED: a pointercancel ends the stroke and keeps what was drawn (the demo does this; the
notebook's cancel grace is not ported).

ASSUMED: after a pen stroke on the page the next click within 500 ms is swallowed (capture phase
on the stack), so a Pencil tap on a link draws a dot and never follows; any new pointerdown
(finger, mouse, a pen on a control) re-enables clicks. A mouse press on a link does not draw, so a
mouse click follows links.

ASSUMED: default ink colour is Obsidian's `--text-normal`, resolved at draw time and repainted on
the workspace's `css-change`. Surfaces' `opts.color` may return a colour or a `--token`.

ASSUMED: long docs draw a band of the page (the visible part plus up to one screen either side,
within 16 M device pixels at full resolution), moved when any scroll leaves it; a short doc is
