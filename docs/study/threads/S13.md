# S13: Ink on figures in problems and drills

Brief by claude, 2026-11-18. Read docs/study/BOARD.md (how to work here), SPEC.md and FORMAT.md first.

**0.15.1 · devin · 4 h · starts now · its cross-view check needs S12, which Claude merges first.**

**Goal.** Adit can write on a circuit's schematic inside a problem statement or a drill prompt (label nodes, draw mesh currents, circle the supernode), in the doc and from Today, with the same strokes in both.

**Scope.**
1. **`figure-ink.ts`** exports two functions with fixed signatures (later tickets reuse the first):
   - `figureSurface(img: HTMLImageElement, env: BlockEnv, key: string): InkSurface | null` wraps the image in a box exactly as wide as the displayed image (`.nb-study-figure`, `display: inline-block`, `max-width: 100%`), sets the image to 100% of the box's width, and, once the image has loaded (`naturalWidth > 0`), mounts `env.ink.surface(env.doc, box, key, { height })` with height = 800 × naturalHeight / naturalWidth paper px. The image is prepended into `surface.el`, under its canvas. It returns null, and adds nothing, when the image never loads.
   - `mountFigureInk(container: HTMLElement, env: BlockEnv, itemId: string): () => void` calls `figureSurface` for each `img` in the container, with key `fig:<itemId>:<file name>`, and returns a cleanup.
2. **Always on:** no button and no read-only mode. The surface has the `.nb-study-ink` class, which page ink already skips, so a figure carries one ink layer. Fingers scroll; only the Pencil (or a mouse) draws.
3. **Open before the call:** figure ink works before the call is made, because labelling nodes is part of reading the circuit (a default Adit may overrule).
4. **A renamed figure** (a new name means a new version, per FORMAT) gets a new key, so a blank surface. The old strokes stay in the file, unshown.
5. **Hooks:** two lines in `problem.ts` after the statement renders, and two in `drill.ts` after the prompt renders. The CSS goes in `drill.ts`'s `BLOCK_CSS`.

**Out of scope.**
- Figures in ordinary passages: page ink already writes over them.
- Figures in solutions.
- Zooming the figure.
- Taps on figure elements.

**Files owned.** `src/study/blocks/figure-ink.ts` (new); the hooks in `src/study/blocks/problem.ts` and `drill.ts`, and their CSS in `drill.ts`'s `BLOCK_CSS`; `test/unit/study-figure-ink.test.ts`; `test/run_study_figure_ink_test.py` (base + 13; reuses the blocks bundle); `test/fixtures/study-figure-ink/*`; its lines in `package.json` (`test` and `test:study`).

**Interfaces touched.** None. Do not assert on an image's `src`: S12 changes how the mock resolves it.

**Acceptance.**
- **Unit:**
  - the key from an item and a file name, including a name with spaces and a URL-encoded name;
  - no surface when the statement has no image, or when the image fails to load;
  - the height from the image's natural size.
- **View** (base + 13):
  - a surface sits over each statement image, exactly as wide as the image;
  - a pen stroke persists after a remount, keyed `fig:`;
  - after the viewport is resized from 1024 to 600 px wide, a stroke still lies over the same image pixel, within 2 px;
  - a renamed figure shows a blank surface;
  - a finger drag over the figure scrolls the view;
  - a hidden pick's view shows nothing new before the settle;
  - the same strokes show in the doc and in the standalone view. This check is SKIP until S12 is merged and `study-mode` is merged into this branch.
- **iPad** (after the release):
  - label the nodes on a schematic in a problem opened from Today;
  - close and reopen it: the ink sits on the same nodes, in portrait and in landscape, and in the doc too.

Design notes before I write code:

- `figureSurface(img, env, key)`: wraps `img` in `.nb-study-figure` (`display:inline-block; max-width:100%`) and sets the image to the box's width. If the image is already known broken (`complete && naturalWidth === 0`) it returns `null` and adds nothing. If loaded (`naturalWidth > 0`) it mounts `env.ink.surface(env.doc, box, key, {height})` with `height = 800 * naturalHeight / naturalWidth` and prepends the image into `surface.el` under the (absolutely positioned, pointer-events:none) canvas. If still loading it wraps now, mounts on `load`, and unwraps on `error`; it returns `null` in that case too (no surface exists yet). A module-private WeakMap keyed by the img tracks each mount so `mountFigureInk`'s cleanup can destroy late-mounted surfaces, cancel pending listeners and restore the DOM.
- Key: `fig:<itemId>:<file name>`, the file name taken from the img's `src` attribute: last `/` segment, query/hash stripped, `decodeURIComponent`d — so `my fig.png` and `my%20fig.png` key identically. A second image resolving to the same name gets `~2` appended (same-name duplicates would otherwise share one stroke set).
- Hooks: `problem.ts` mounts figure ink on `.nb-sb-stmt` after `env.render` of the statement resolves (covers the doc block, the hook card and the standalone view, since all go through `mountSession`); `drill.ts` mounts it on `.nb-sb-prompt` after the prompt renders (covers derives, cold proofs and recall prompts via `runDrill`). Cleanup runs in each block's `destroy`.
- CSS goes in `drill.ts`'s `BLOCK_CSS` as the brief says, not styles.css (S12 owns the image rules there).
- No INTERFACE needed: `env.ink.surface` already does everything; `.nb-study-ink` is already in `PAGE_INK_SKIP`, so page ink never starts on a figure and the figure carries exactly one ink layer. Finger drags: the surface only acts on pen/mouse pointerdowns; a touch pointerdown returns early and no touch action is prevented, so the view scrolls.
- Same strokes in doc and standalone view come free once S12 lands (its `env.doc` becomes the home doc, so `fig:` strokes file under the same ink file). Until then the standalone view files them under `problems.<device>.json`, like `call:`/`work:` do today.
